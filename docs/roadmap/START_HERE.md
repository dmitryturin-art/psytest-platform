4. Если есть субагенты, основному исполнителю — **K0a**, независимому — **S1** в отдельном worktree.
   Если работаешь один — **S1**, затем K0a; так СМИЛ снова не откладывается за бесконечным инфраструктурным слоем.
5. Назови владельцу пакет и начинай. Обычные обратимые действия уже разрешены. После пакета переходи

## 2. Что действительно требуется владельцу

- **СМИЛ:** довести все дополнительные шкалы выбранного подтверждённого источника. Полнота — реестр
  с точным знаменателем и статусом каждой записи; «первая партия готова» не означает «СМИЛ доделан».
- **Специалист:** создать подписанное назначение Лазаруса, скопировать ссылку, увидеть прохождение,
  открыть ответы по пунктам и рассчитанный результат клиента. Первый срез — индивидуальный Лазарус.
- **Посетитель:** добровольный вход по email и история своих прохождений; тесты без регистрации остаются.
- **Открытые методики:** IPIP рядом со СМИЛ; затем отдельные PHQ-9/GAD-7/CSI. Форма/перевод и назначение
  требуют источников, клиническая эквивалентность не предполагается. Платёжный контур отложен.

Сделай **реестр данных**, а не очередное эссе: стабильный ID, название, страница PDF/печатная,
true/false keys, нормы по форме, происхождение, existing/new, verified/disputed/missing.

Сверь 23 существующие шкалы только чтением; отдельно перечисли расхождения.
Полную книгу повторно не распознавай: извлекай нужное приложение. Не коммить сканы/OCR cache.

Готово, когда: весь перечень источника учтён; нет потерянных/двойных ID; для всех 23 есть статус
сверки и страницы; указан следующий пакет S2 и конкретные пробелы. **Ноль изменений scoring,
норм и expected fixtures.** Спорные ключи/нормы принеси владельцу; не «исправляй» расчёт автоматически.

### K0a — удалить связанный ИИ-отчёт при удалении результата (R7)

Готово, когда: ready/pending/running-артефакты удаляются или необратимо очищаются; повтор удаления

## 5. Метод работы и сдача

- Не повторяй общий аудит, не читай все skills/phase-файлы, не запускай массовую Graphify extraction
  автоматически. Проверяй релевантные исходники; stale-граф не доказательство. Freshness policy AGENTS сохраняется.
- Параллельность по независимым файлам/worktrees. Один ведущий объединяет STATUS/WORKLOG и миграции;
  субагенту передавать scope, критерии и запреты, не весь архив. При единственной модели работай последовательно.
- Изменение доступа, удаления, очереди — поведенческий regression test. Поиск строки в исходнике
  не считается проверкой безопасности. UI — настоящий браузер 390×844 и desktop по полному сценарию.
- DB gate: `bin/local-gate.sh` на изолированном Docker MySQL. Сначала миграции, затем PHPUnit.
  Если команда упала на sandbox/DNS/socket, проверь инфраструктуру и разрешённый запуск;
  не объявляй Docker выключенным по одному EPERM и не запускай миграции на production.
- До передачи: узкие тесты → соразмерный gate → diff review → WORKLOG/STATUS/phase → точный commit.
  В STATUS только текущие факты, в WORKLOG хронология. Не дублируй очереди задач в новом отчёте.
- Покажи владельцу проверенный результат и следующий ID. Если пакет зависит от конкретного решения,
  принеси конкретный вопрос; остальная независимая линия продолжается. Push/deploy не подразумеваются.

# Ежедневная очистка данных (cleanup cron) — настройка в панели Beget

Для ИИ-разборов расписание не нужно — они доготавливаются сами; подробности в [CRON_AI_REPORTS.md](CRON_AI_REPORTS.md).

Статус: **настроено владельцем 25.08.2026** (расписание 03:17 ежедневно, команда соответствует инструкции ниже).

Зачем: платформа обещает пользователям, что анонимные данные удаляются через 180 дней
(утверждённая retention-policy). Скрипт `bin/cleanup-sessions.php` это удаление выполняет,
но сам он не запускается — нужен планировщик (cron), который дёргает его раз в сутки.

Путь специально стабилен: `current` — симлинк на активный релиз, он обновляется
при каждом деплое, поэтому команду cron менять никогда не придётся.

## Что сделать в панели Beget (один раз, ~2 минуты)

1. Панель Beget → раздел «Cron» (Планировщик заданий) → «Добавить задание».
2. В поле команды вставить ровно одну строку:

   ```
   /usr/local/bin/php8.3 /home/q/qdesign/test.23time.ru/current/bin/cleanup-sessions.php >/dev/null 2>&1
   ```

3. Расписание: раз в сутки, например `17 3 * * *` (03:17 ночи).
4. Сохранить.

## Как проверить, что работает

- Через сутки: в файле `/home/q/qdesign/test.23time.ru/current/storage/logs/cleanup.log`
  должна появиться свежая строка вида
  `cleanup.INFO: Cleanup completed {"sessions_deleted":N,"retention_days":180}`.
- Либо вручную по SSH:
  `/usr/local/bin/php8.3 /home/q/qdesign/test.23time.ru/current/bin/cleanup-sessions.php`
  — должен вывести `✓ Cleanup completed: ...` и завершиться кодом 0
  (проверено 25.08.2026: `0 anonymous sessions removed`, EXIT=0).

## Что скрипт делает

- Удаляет истёкшие anonymous-сессии старше 180 дней вместе со связанными
  ответами, результатами, парными сравнениями и известными PDF (интеграционные
  тесты покрывают каждый тип сущности).
- Удаляет записи `activity_log` старше 90 дней.
- `therapist_case` не трогает — их удаляет только владелец вручную через `/admin`.

## Чего не делать

- Не запускать скрипт от другого PHP (нужен именно `/usr/local/bin/php8.3`).
- Не менять путь команды на прямой путь релиза (`releases/<sha>/...`) — он
  устареет после следующего деплоя; стабильный путь — только через `current`.

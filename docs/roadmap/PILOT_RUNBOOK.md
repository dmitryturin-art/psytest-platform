# Закрытый бесплатный пилот

Статус: **подготовлен к запуску после настройки staging**. Этот документ относится только к бесплатным сценариям и не является production-runbook.

## Границы пилота

В пилот входят:

- каталог из пяти текущих методик;
- прохождение без регистрации;
- бесплатный базовый результат и PDF;
- одиночный и парный сценарий Lazarus;
- канонический профиль SMIL;
- утверждённое сообщение BDI при положительном ответе на пункт 9;
- удаление результата и минимальный защищённый кабинет владельца.

В пилот **не входят** оплата, купоны, платный CTA, внешний ИИ, AI-отчёты, пользовательские аккаунты и обещания production-готовности. Retired payment/AI routes должны продолжать отвечать `410 Gone`.

## Условия запуска

- Отдельный закрытый staging с HTTPS и document root на `public/`.
- PHP 8.3+, MySQL 8 и отдельная от production база данных.
- `APP_DEBUG=false`; секреты заданы только в server environment.
- Staging закрыт общей авторизацией или доступен только приглашённым участникам и имеет `noindex`.
- Для `/admin` задан отдельный Argon2id hash; пароль не передаётся участникам.
- Миграции применены на чистой staging-базе; полный quality gate зелёный.
- Настроен ежедневный запуск `bin/cleanup-sessions.php` и проверен его журнал без клиентских данных.
- Перед первым приглашением сделан backup базы и записан простой способ отката текущего релиза.

Если хотя бы одно условие не выполнено, пилот не открывается участникам.

## Smoke-check перед приглашением

Проверить на desktop и экране 390×844:

1. `/tests` открывается по HTTPS, не имеет горизонтальной прокрутки и показывает пять методик.
2. BDI с полным набором допустимых ответов завершается и открывает результат.
3. При BDI item 9 = 0 специальное сообщение отсутствует.
4. При BDI item 9 > 0 утверждённое сообщение видно до блока действий; в нём нет телефона, ссылки, страны или GeoIP.
5. SMIL открывает канонический график с L/F/K, разрывом и шкалами 1–9/0; hover показывает точные значения.
6. Lazarus проходит в одиночном режиме; приглашение пары используется только один раз и приводит к сравнению.
7. PDF BDI, SMIL и Lazarus скачивается и читается.
8. Ссылка результата другого теста не открывает данные; истёкшая или неверная ссылка обрабатывается без stack trace.
9. Удалённый public result больше не открывается.
10. Владелец входит в `/admin`, назначает завершённый результат как `therapist_case` и вручную удаляет тестовый кейс.
11. `/interpretation/...`, endpoint оплаты и retired webhook не принимают работу и отвечают `410`.
12. В HTML результата есть запрет индексации; result token не появляется в обычных server access/error logs.

Для smoke-check использовать только искусственные ответы. Реальные данные клиентов в screenshots, issue-тексты и Git не копировать.

## Как проводить пилот

- Первая волна: владелец и 2–3 приглашённых участника.
- Вторая волна возможна только после разбора первой: до 10 участников одновременно.
- Участнику заранее сообщается, что это закрытая бесплатная проверка и платного/AI-функционала пока нет.
- Канал поддержки: личный контакт владельца, по которому он пригласил участника. Отдельную публичную службу поддержки пилот не обещает.
- После каждого сообщения сначала воспроизвести дефект на искусственных данных; не просить присылать полный результат или ответы.

## Журнал замечаний

Замечания ведутся без имени, email, result token, ответов, текста результата и иных клиентских данных.

| Поле | Что записывать |
|---|---|
| ID | `PILOT-001`, `PILOT-002`, … |
| Дата | дата обнаружения |
| Экран/методика | например, `BDI result`, без ссылки результата |
| Среда | браузер, ОС, размер экрана |
| Шаги | минимальные действия на искусственных данных |
| Ожидалось / произошло | краткое сравнение |
| Severity | `P0`, `P1`, `P2` или `P3` |
| Статус | `new`, `reproduced`, `fixed`, `verified`, `accepted` |
| Evidence | test/commit/CI без персональных данных |

Severity:

- `P0` — раскрытие чужих данных, неверный расчёт, обход доступа или опасная клиническая ошибка;
- `P1` — потеря результата, невозможность завершить основной сценарий или существенная privacy-проблема;
- `P2` — заметный функциональный/UX-дефект с обходным путём;
- `P3` — косметика или небольшая понятностная проблема.

При `P0` пилот немедленно закрывается. При `P1` затронутый сценарий выключается либо пилот приостанавливается до исправления. `P2/P3` регистрируются и планируются небольшими пакетами.

## Завершение пилота

Пилот этапа 02 можно считать пройденным, когда:

- smoke-check выполнен без `P0/P1`;
- первая и вторая волны не оставили незакрытых `P0/P1`;
- каждый найденный дефект имеет ID и решение;
- владелец подтвердил, что бесплатный flow достаточно понятен для перехода к Module API/UI-прототипам;
- staging остаётся закрытым, пока не выполнены production gates этапа 08.

Прохождение этого пилота не разрешает включать оплату или внешний ИИ: для них действуют отдельные этапы 06 и 07.

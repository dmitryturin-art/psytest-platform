# Элементы интерфейса: что уже есть и что переиспользовать

**Статус:** первая опись от 27.08.2026. Составлена по фактическому содержимому `public/css/main.css`,
а не по замыслу. Дополняется при появлении новых общих элементов.

## Зачем

Одинаковые по смыслу элементы должны выглядеть одинаково. Повод для документа конкретный: блок
расширенного разбора был сделан со своим оформлением, хотя рядом на той же странице уже жил
раскрывающийся блок «Подробное сравнение по 16 пунктам». Владелец заметил расхождение сразу.

**Правило: новый блок берёт существующий класс. Свой класс заводится, только если нужного элемента
в этой описи нет — и тогда он сюда добавляется.**

## Основа

Цвета, отступы, скругления, тени и шрифты заданы переменными в начале `main.css`. Собственные значения
в новых правилах не пишутся: берутся `--color-*`, `--spacing-*`, `--radius-*`, `--shadow-*`.

Основной акцент — `--color-primary`. Опасное действие — `--color-danger`. Успех — `--color-success`.
Приглушённый текст — `--color-text-light`.

## Кнопки

Базовый класс `.btn` плюс вид:

| Класс | Когда |
|---|---|
| `.btn-primary` | главное действие на экране |
| `.btn-secondary` | второстепенное действие |
| `.btn-success` | подтверждающее действие |
| `.btn-danger` | необратимое действие, например удаление |
| `.btn-outline` | действие в плотном окружении |
| `.btn-sm` | уменьшенный размер |
| `.btn-block` | на всю ширину |

Своих кнопок не делать: если нужного вида нет — обсуждать, а не изобретать.

## Карточка блока результата

Белый фон, `--spacing-xl` внутренних отступов, `--radius-lg`, `--shadow-md`. Так оформлены
`.pair-comparison` и `.ai-report`. Новый крупный блок на странице результата берёт то же самое.

## Раскрывающийся блок

Для длинного содержимого, которое не должно разворачиваться сразу. Разметка — `details` и `summary`,
оформление одинаковое у `.pair-comparison__details` и `.ai-report__details`: голубая шапка, левая полоса
акцента, круглая кнопка «плюс», превращающаяся в «минус» при раскрытии, высота шапки не меньше 48 пикселей.

## Плашки-уведомления

| Класс | Смысл |
|---|---|
| `.clinical-safety-notice` | клиническое предупреждение на странице результата |
| `.owner-notice--success` / `.owner-notice--error` | итог действия в кабинете владельца |
| `.ai-report__waiting` | процесс идёт: подсветка и вращающийся индикатор |
| `.ai-report__error` | не получилось, с причиной |
| `.results-disclaimer` | постоянная оговорка внизу результата |

У всех общая логика: цветная левая полоса, фон того же оттенка, отступ `--spacing-md`, размер текста
`--font-size-sm`. Новое уведомление строится по этому образцу.

## Шкала с отметкой

`.score-badge__scale` — полоса с цветными зонами и маркером текущего значения. Ось берётся из порогов
методики, а не от нуля: это исправление дефекта, найденного владельцем 26.08. Подключается включением
`blocks/score-scale.twig`, самостоятельно не рисуется.

## Таблицы

`.report-table` внутри `.report-table-scroll` — рамки, фон заголовка, чередование строк и горизонтальная
прокрутка внутри контейнера. Широкая таблица никогда не растягивает страницу: на телефоне прокручивается
она сама.

## Подключение стилей

Ссылки на стили и скрипты ставятся через `{{ asset('css/main.css') }}`. Функция добавляет к адресу время
изменения файла, поэтому браузер не показывает старую копию после выкладки. Прямые ссылки вида
`{{ basePath }}/css/...` не использовать: именно из-за такой ссылки новое оформление однажды не дошло
до владельца.

## Что предстоит сделать

1. **Живая страница элементов** на служебном адресе: все кнопки, плашки, раскрывающиеся блоки, шкалы
   и таблицы показаны рядом. Расхождение видно глазами за секунду.
2. **Тест против устаревания** этой страницы: если появился новый общий элемент, а на странице его нет —
   тест падает. Иначе опись повторит судьбу любой документации, которую никто не сверяет.
3. Проверка на 390×844 и на десктопе — обязательна для любого изменения оформления (`AGENTS.md`).

# Элементы интерфейса: что уже есть и что переиспользовать

**Статус:** обновлено 06.10.2026 (04.D1, этап 1 дизайна; 04.D2 — прототип «лёгкого кабинета»).
Направление — «спокойный редакционный» (вариант B, выбор владельца 05.10) плюс зебра в таблицах
из варианта A. Опись составлена по фактическому содержимому `public/css/main.css` и слоя кабинета
`public/css/cabinet.css`, а не по замыслу.

## Зачем

Одинаковые по смыслу элементы должны выглядеть одинаково. **Правило: новый блок берёт существующий
класс. Свой класс заводится, только если нужного элемента в этой описи нет — и тогда он сюда
добавляется.**

## Основа: переменные

Все цвета, шрифты, размеры, радиусы, отступы и тени заданы одним блоком `:root` в начале `main.css`.
Собственные значения в новых правилах не пишутся.

## Шрифты

Собственный хостинг в `public/fonts/`, внешние хосты не используются:

- **Inter** (переменный, 100–900) — текст, интерфейс, таблицы; табличные цифры включены для всех
  `table` (`font-variant-numeric: tabular-nums`);
- **PT Serif** 400/700 — заголовки `h1–h3`, логотип, номера и названия шкал в толковании.

Наборы разделены на кириллицу и латиницу (`unicode-range`), 6 файлов woff2, 184 КБ. Источник —
пакеты @fontsource 5.3.0; лицензия SIL OFL 1.1 — `public/fonts/LICENSE-*.txt`.

## Кнопки

Базовый класс `.btn` плюс один из трёх видов. Все кнопки — «пилюли» высотой не меньше 44 px.

| Класс | Вид | Когда |
|---|---|---|
| `.btn-primary` | залитая акцентом | главное действие на экране |
| `.btn-outline` | контур 2 px | второстепенное действие |
| `.btn-danger` | красный контур, заливка при наведении | удалить, отозвать, необратимое |
| `.btn-sm` | уменьшенная, 36 px | плотные служебные места (промпты) |
| `.btn-block` | на всю ширину | — |

`.btn-secondary` и `.btn-success` убраны: в шаблонах их нет. Своих кнопок не делать.
В формах кабинета (`.owner-form`, `.owner-action-form`) кнопка по ширине текста.

### Кнопки в кабинете специалиста (04.D2)

На страницах кабинета (`body.owner-dashboard-page`, слой `cabinet.css`) те же классы выглядят тише:
прямоугольник со скруглением 8 px, контур 1 px, высота 40 px (`.btn-sm` — 34 px), на сенсорном
экране 44 px. **Одна основная кнопка на экран** — остальные тихие.

| Класс | Вид в кабинете | Когда |
|---|---|---|
| `.btn-primary` | мятная заливка #DDEBE3, тёмно-зелёный текст (6.9:1), значок «+» у создающих | одно главное действие экрана: «Создать ссылку», «Создать карточку», «Создать назначение» |
| `.btn-outline` | белая, контур в волосок #DCD4C8, чернильный текст | второстепенное: «Сохранить», «Найти сессию», «Применить» без JS |
| `.btn-ghost` | без контура, вторичный текст | служебное: «Снять выбор» |
| `.btn-danger` | белая, контур в волосок, красный только текст; тинт при наведении | необратимое вне меню: «Удалить клиента полностью» |
| `.owner-dialog .btn-danger` | залитая красным (6.65:1) | подтверждение в диалоге — это и есть решение |

Значок в кнопке ставится перед подписью: `{{ ui.icon('plus') }}Создать ссылку`. Подпись с
значком переживает «Назад» из кэша: `owner-forms.js` хранит `innerHTML`, а не `textContent`.

## Статусы

Метка-«пилюля» на тинте: `<span class="status status--<тон>">подпись</span>`. Тон для состояний
сессии и приглашения даёт фильтр `status_tone` (словарь в `OwnerLabels::tone`, рядом с русскими
подписями `status_label`).

| Тон | Состояния |
|---|---|
| `status--done` | завершено, опубликовано |
| `status--open` | открыто, в процессе |
| `status--pending` | ожидает открытия |
| `status--muted` | отозвано, срок истёк, результат удалён |
| `status--failed` | удалено |

Та же форма у `.validity-status` (контрольные шкалы СМИЛ) и `.ai-report__published-at`.

В кабинете (04.D2) `.status` — без заливки: цветная точка `--status-dot-*` и подпись чернилами
(у `--muted` подпись вторичная, у `--failed` — тёмно-красная). Смысл несёт подпись, точка только
помогает глазу. Отметка архива и корзины рядом — `.status-flag` (тонкая рамка, 13 px;
`--trash` — красноватая).

## Карточки

- `.owner-panel` — кабинет специалиста: белая карточка, рамка, `--radius-lg`, `--shadow-md`,
  отступы 48/56 px (на телефоне 24/18). `.owner-login-panel` — узкая 440 px. В слое кабинета
  тень легче (`--shadow-sm`), надпись над заголовком `.owner-panel-eyebrow` — обычным регистром
  вторичным цветом, без разрядки капсом.
- `.results-content` — карточка результата той же формы. Блоки внутри неё (`.interpretation-block`,
  `.pair-comparison`) второй карточкой не оформляются.
- `.ai-report`, `.account-wrapper` — та же карточка для разбора и кабинета посетителя.
- Вложенные элементы (`.owner-invite-list li`, `.owner-case-ai-item`, `.owner-revision`) — `--color-bg-soft`
  с рамкой, без тени.
- `.owner-case-details` — реквизиты кейса сеткой на бумажной подложке; длинное значение —
  `.owner-case-details__wide`.

## Таблицы

Одна система для `.scores-table`, `.lazarus-items-table`, `.pair-comparison__table` и `.report-table`:
без боковых рамок, только горизонтальные разделители, тонированная шапка, зебра по строкам
(`tbody tr:nth-child(even)`), табличные цифры. Смысловые тинты строк (`level--above/below`,
`row-diff-0`, `category-header`) объявлены после и перекрывают зебру. Широкая таблица живёт в
`.table-scroll` / `.report-table-scroll` и прокручивается сама — страница вбок не уезжает.

## Раскрывающийся блок

`details` + `summary`, одинаково у `.pair-comparison__details` и `.ai-report__details`: тонированная
шапка акцента, левая полоса, круглый «плюс/минус», высота шапки не меньше 48 px.

## Плашки-уведомления

| Класс | Смысл |
|---|---|
| `.clinical-safety-notice` | клиническое предупреждение на странице результата |
| `.owner-notice--success` / `--error`, `.account-flash` | итог действия в кабинете |

Общая логика: тинт фона, левая полоса цвета текста, `--radius-sm`, ширина не больше колонки текста.

## Шкала с отметкой

`.score-badge__scale` — полоса с цветными зонами (`--zone-*`) и маркером. Ось берётся из порогов
методики. Подключается включением `blocks/score-scale.twig`.

## Списки кабинета: фильтры, таблица, меню строки, выбор и подтверждение (07.K8 → 04.D2)

Три списка кабинета — приглашения (`/admin`), клиенты (`/admin/clients`) и назначения в карточке
клиента — собраны из одних и тех же частей. Стили — в `cabinet.css`.

- **Шапка списка** `.list-head`: заголовок `h2` слева, переключатель вида `.view-tabs` справа —
  «Рабочие · Архив · Корзина» со счётчиками `.view-tabs__count`; текущий вид — `aria-current="page"`
  (белая плашка, тёмно-зелёный текст).
- **Фильтры** `.filter-bar`: одна лёгкая строка без рамки. Подписи полей скрыты (`.visually-hidden`),
  первый пункт списка сам говорит, что выбрано («Все клиенты»). Поиск — `.filter-bar__search` со
  значком лупы. Форма помечена `data-auto-submit`: со скриптом `owner-cabinet.js` выбор сразу
  обновляет список, пустые поля в адрес не попадают, а кнопка `.filter-bar__apply` прячется
  (без скрипта она видна и работает). «Сбросить» — текстовая ссылка `.filter-bar__reset`.
  `.filter-counts` — тихая строка «Показано: N»; пояснение к архиву/корзине после неё — 14 px.
- **Таблица** `.cab-table` (+ `.invite-table`, `.client-table`, `.assignment-table` для отличий):
  фиксированная раскладка, шапка 13 px вторичным цветом без заливки, строки 14 px сверху и снизу,
  зебра, наведение `--color-hover` (только на устройствах с мышью), отмеченная строка —
  `--color-primary-tint`. Первая колонка `.cab-table__main`: название `.cab-table__title` и заметка
  `.cab-table__sub` в одну строку с многоточием (полный текст — в `title`). Узкие колонки:
  `__check`, `__client`, `__status`, `__date`, `__num`, `__actions`. Даты — в `<time>`, табличные
  цифры. Клиент в строке — тихая ссылка `.quiet-link`.
- **Флажок** `.cab-check`: свой вид, контур 3:1, отмечен — заливка акцентом с галочкой,
  «частично» — черта. Недоступный (действующая ссылка) — бледный, с подсказкой в `title`.
- **Действия строки** — `blocks/owner-invite-actions.twig`: `.row-actions` = ссылка
  `.row-actions__open` («Открыть кейс») + одно меню `.row-menu` («⋯»). Меню — нативный
  `<details>`/`<summary>` с `aria-label`; пункты `.row-menu__item` со значком и подписью,
  опасные — `--danger` (красный текст, тинт при наведении), отделены `.row-menu__sep`.
  Пункты архива/корзины — кнопки общей формы (`form`, `formaction`, `invite_id`), «Отозвать» и
  мгновенное «Удалить» — свои POST-формы `.row-menu__form` (только при `lifecycle: true`).
  `owner-cabinet.js`: открыто одно меню, Escape закрывает и возвращает фокус, щелчок мимо или по
  пункту закрывает, у нижнего края окна список раскрывается вверх (`.row-menu--up`). Без скрипта
  меню открывается и закрывается само.
- **Панель выбранного** `.bulk-bar` / `.bulk-bar__inner`: всплывает по центру у нижнего края,
  белая с тенью `--shadow-pop`; скрыта атрибутом `hidden`, пока ничего не отмечено. Кнопки —
  тихие со значками, «Снять выбор» (`data-bulk-clear`) появляется только со скриптом.
- **Диалог** `.owner-dialog`: один нативный `<dialog>` на страницу, без рамки, скругление 16 px,
  тень `--shadow-dialog`, лёгкое затемнение фона; `margin: auto` обязателен из-за общего сброса.
- **Телефон (≤600 px)**: строки становятся карточками, подпись столбца — из `data-label`; флажок —
  в левом верхнем углу, меню «⋯» — в правом верхнем, внизу карточки только «Открыть кейс».
- Включения: `blocks/owner-invite-status.twig` (статус + `.status-flag`),
  `blocks/owner-invite-actions.twig`, `blocks/owner-invite-dialog.twig`.

## Значки

Встроенный SVG-спрайт `templates/blocks/icons.twig`: сетка 20×20, линия 1.5, `currentColor`,
без шрифтов значков и внешних хостов. Спрайт выводит `layout.twig` один раз на странице кабинета;
в шаблоне — `{% import 'blocks/icons.twig' as ui %}` и `{{ ui.icon('archive') }}` (класс `.icon`,
18 px; в кнопках и вкладках 16 px). Значок всегда рядом с подписью или у кнопки с `aria-label` —
сам он скрыт от экранного диктора.

Есть: `open`, `archive`, `unarchive`, `trash`, `delete`, `restore`, `revoke`, `filter`, `search`,
`more`, `check`, `close`, `client`, `calendar`, `plus`. Новый значок добавляется в спрайт; тест
`OwnerDashboardContractTest` проверяет, что каждый `ui.icon('…')` в шаблонах есть в спрайте.
Использовать скупо: меню с подписями, фильтр, панель выбранного, главная кнопка создания.

## Что не входит в систему

- Канонический график СМИЛ (`.classic-profile-*`, `smil-profile-classic.js`, бланк) — защищённый
  компонент, переменные системы не использует.
- PDF (результат, выгрузка кейса) — DomPDF со своими встроенными стилями, `main.css` не подключает.
  Растр PDF результата СМИЛ после 04.D1 побайтно совпадает с прежним.
- Публичная главная и каталог — свой слой `editorial-catalog.css`; его переменные `--editorial-*`
  берут значения из общей системы.
- Кабинет специалиста — свой слой `cabinet.css` (04.D2): подключается в `layout.twig` только при
  `ownerArea`, общие классы (`.btn`, `.status`, `.owner-panel`) меняет только под
  `.owner-dashboard-page`, цвета берёт из `:root` (исключение — стрелка списка в data-URI).
  Страницы прохождения теста, результата и PDF его не видят.

## Подключение стилей

Ссылки на стили и скрипты ставятся через `{{ asset('css/main.css') }}`: функция добавляет время
изменения файла, браузер не показывает старую копию после выкладки.
